# Baseline Audit — Plot Docs 1.0.0

Status: evidence-based audit of the repository at commit `208a8f0d`, 2026-10-23.

## 1. Product baseline

Plot Docs is a local-first Electron desktop workspace. It opens and saves real
Office files and includes Docs (`.docx`), Sheets (`.xlsx`), Slides (`.pptx`),
PDF, Markdown and HTML editors. Soopus AI is the default AI provider. A local
Plot Docs account is separate from the optional Soopus cloud login.

## 3. Workspace layout

### Applications

- `apps/shell` — Electron main process, preload, Home renderer, tab manager,
  settings, search, MCP, local accounts, updates.
- `apps/docs` — DOCX editor and the shared AI IPC registration.
- `apps/sheets` — XLSX editor and spreadsheet engine.
- `apps/slides` — PPTX editor.
- `apps/pdf` — PDF editing and annotations.
- `apps/markdown` — Markdown editor.
- `apps/html` — HTML editor.

### Shared packages

`agent-core`, `ai-provider`, `ai-search`, `cli`, `docx-engine`,
`electron-utils`, `file-parse`, `font-metrics`, `html2docx`, `i18n`,
`odf2ooxml`, `pdf2docx`, `pipelines`, `pptx-engine`, `pptx-ops`,
`pptx-render`, `project-store`, `ui`, `xlsx-gateway`, `zip-gate`.

## 4. Protected document-generation subsystem

The following are treated as frozen for this project:

- Home "AI Docs / AI Sheets / AI Slides / AI Markdown / AI HTML / AI PDF"
  actions and their quick cards.
- Template catalog and `newFromTemplate`.
- Open Local File and file routing.
- Every editor renderer, its prompts, generation logic, formatting, save/export
  behavior and tests.
- Shared AI prompts and the existing AI panel workflows.

Primary files that must not be modified for analytics work:

- `apps/shell/src/renderer/src/Home.tsx` quick-card actions (only additive card
  placement is allowed).
- `apps/shell/src/shared/templates.ts` and template assets.
- `apps/docs`, `apps/sheets`, `apps/slides`, `apps/pdf`, `apps/markdown`,
  `apps/html` renderer/editor code.
- Existing `ai:stream` and `ai:chat` request shapes.
- Existing document file formats, export code and template logic.

The analytics workspace is a sibling module. It must not route through or
redirect any existing document-generation action.

## 5. AI integration baseline

- Provider implementations and settings live in `packages/ai-provider`.
- Shell main registers the shared AI IPC in `apps/docs/src/main/docs-main.ts`
  via `registerAiIpc()`.
- Channels: `ai:get-settings`, `ai:set-settings`, `ai:stream`,
  `ai:stream-cancel`, `ai:stream-chunk`, `ai:chat`, `ai:soopus-status`.
- Settings live in `userData/ai-settings.json`.
- The Soopus key is not stored in the settings file; it is injected by the main
  process from the Soopus login/key chain (`@plotdocs/ai-search`).
- The renderer can reuse `window.aiOffice.aiGetSettings()` and
  `window.aiOffice.aiStream()` without a new provider implementation.
- Existing one-shot calls use `chatForProvider()`; streaming uses
  `streamForProvider()`. Both are exported by `@plotdocs/ai-provider`.

## 6. Persistence baseline

- No general relational application database exists today.
- Preferences live in JSON under `userData` (for example
  `app-settings.json`, `ai-settings.json`).
- Project/chat data is stored by `packages/project-store` (JSON-based store).
- File search uses `node:sqlite` with an FTS5 index in
  `apps/shell/src/main/file-index/store.ts`.
- Document files remain in the user's folders.
- Therefore, adding an analytics database is additive and does not require a
  migration of existing editor data.

## 7. Home and navigation baseline

- `AppFrame` renders the persistent `TabBar` and Home.
- Home quick cards are generated by `renderQuickCards()` in
  `apps/shell/src/renderer/src/Home.tsx`.
- Sidebar entries are Recent, Starred, Ask AI, optional Soopus Projects.
- Tabs are managed in `apps/shell/src/main/tab-manager.ts`; a new tab kind is
  more invasive than an in-Home workspace.
- Decision: add one Analytics quick card and an overlay workspace inside the
  Home shell. Do not add a new editor tab kind in the first slice.

## 8. Security baseline

- `contextIsolation: true`, `sandbox: true`, no `nodeIntegration` in renderers.
- Preload exposes a narrow API; IPC payloads are validated in main.
- Navigation guards and external URL checks exist.
- Local files are opened through explicit user actions.
- The AI settings payload is schema-checked in main.
- New analytics IPC must validate all IDs, SQL, file types, sizes and paths;
  SQLite queries must be read-only; uploaded files must be size-capped.

## 9. Build and test baseline

Commands:

```text
npm run typecheck
npm run test
npm run format:check
npm run check:help-langs
npm run check:theme-colors
npm run build:all
npm run dist:win
```

Known environment limitation: the root `dist:win` native sheets sidecar build
is blocked by Device Guard on this machine. The shell-only package build works
with the existing native sidecar. This is unrelated to analytics.

## 10. Regression gate for this project

Before and after each analytics phase:

1. `npm run typecheck -w @plotdocs/shell`
2. `npm run test -w @plotdocs/shell`
3. Existing editor smoke checks: create/open/edit/export one document of each
   format available in the build.
4. Verify Home quick cards still call the original APIs.
5. Verify no analytics code is imported by editor renderers.
6. Verify analytics startup failure cannot block app startup.

## 11. Integration points selected

- New additive quick card in `Home.tsx` that calls a new callback.
- New `AnalyticsWorkspace` rendered by `AppFrame` next to Home.
- New `analytics-api.ts` shared types and IPC channel constants.
- New preload bridge `window.plotdocsAnalytics`.
- New shell-main `analytics/` service registered once after app ready.
- Separate SQLite database under `userData/analytics/`; one database per
  imported dataset, plus a metadata database.
- Reuse `@plotdocs/xlsx-gateway` parsers for CSV/TSV and XLSX.
- Reuse `@plotdocs/ai-provider` for the AI analyst.

Backend behavior:
- Dev folder default: repo-root updates/ and notifications/.
- Packaged folder default: %APPDATA%/Plot Docs/updates and notifications; writable exe-adjacent folders are also watched.
- Env overrides: PLOTDOCS_UPDATES_DIR, PLOTDOCS_NOTIFICATIONS_DIR, PLOTDOCS_GITHUB_REPO, PLOTDOCS_GITHUB_TOKEN/GITHUB_TOKEN/GH_TOKEN.
- GitHub default repo: sukhee-2626/plot-docs.
- Checks latest GitHub release on launch, manual request, and focus (15-minute throttle). No polling interval.
- GitHub asset selection: portable .exe on Windows; setup/installer assets are download-only and never auto-run.
- Download streams to .part, computes SHA-256, verifies published digest when available, removes interrupted partial files.
- Duplicate download prevention: reuse matching existing file; reject concurrent download; reject same-name checksum mismatch.
- Install requires explicit confirmation.
- Only portable .exe can replace the running executable.
- Windows Authenticode check is best-effort. Invalid signatures are blocked. Unsigned/unknown requires an extra acknowledgement.
- Backup is copied to updates/backups before replacement.
- Replacement renames the running exe aside, copies the new exe into place, and requires a user-triggered restart.
- No installer is executed automatically.
- Notification JSON files support one object, an array, or { notifications: [...] }.
- Read/unread state and deleted tombstones are stored in notifications/state.json.
- Update history/installed records are stored in updates/state.json; logs in updates/logs/update.log.
- Real-time fs.watch with 250 ms debounce; watcher retries after errors.

UI behavior:
- Bell is in the tab strip, always visible.
- Unread count badge; green update dot.
- Bell opens the panel on Home (activates Home tab first because editor WebContentsViews paint above shell DOM).
- Bell opens Updates directly when an update is waiting; otherwise Notifications.
- Panel tabs: Notifications and Updates.
- Notifications: type chips, date, source file, mark read, mark all read, delete with confirmation.
- Updates: GitHub release card, release notes, download progress, local package cards, status chips, checksum/signature indicators, inline install confirmation, unsigned warning, restart banner, update history, folder paths/open buttons.
- Toast appears for newly detected unread notifications.
- Update popup: one prominent card per version per session with version, release-note summary, View update, Later, and close. Opening the panel acknowledges it. A fresh launch while the update is still available shows it again.
- Panel update hero: persistent "Update available - vX.Y.Z" strip above the tabs, even when Notifications is selected. After install it becomes "Restart to finish the update" with Restart now.
- No forced restart; the user keeps working and restarts when ready.

SECURITY / PRODUCT RULES
-----------------------
- Never fabricate analytics results. Show SQL, dataset, filters, period, method, uncertainty.
- Keep source datasets immutable; derived datasets for joins/appends.
- Do not auto-execute downloaded installers or untrusted executables.
- Do not disable Smart App Control in app code.
- Verify checksums; check signatures; require explicit confirmation.
- Preserve user documents/settings during updates.
- No continuous polling for GitHub. Startup + manual + throttled focus only.
- Renderer never supplies arbitrary file paths or download URLs to main.
- All update/notification paths are resolved in main.
- Privacy: redact identifiers, strip signed URL query strings, mask DB secrets.
- Imports require user-supplied absolute paths.
- No agents/subagents.

VERSION CONTROL / GITHUB WORKFLOW
---------------------------------
See docs/version-control-workflow.md. Short version:
1. Work on main only if the user accepts it; otherwise create a feature branch.
2. Commit in small logical chunks with conventional messages.
3. Push to origin main.
4. Bump package version before release.
5. Build portable exe.
6. Create a GitHub release with tag vX.Y.Z.
7. Attach the portable .exe and, optionally, a manifest with SHA-256.
8. The app checks the latest GitHub release and offers the update.
